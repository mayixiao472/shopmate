# 置信度闸门与数据飞轮

> 决策文档。写的是「为什么这么做」,实现细节看代码与测试。

## 要解决的问题

RAG Agent 最怕**证据撑不住还硬答**——检索弱时编出一段假政策,比「答不上」伤害大得多。同时,「答不上」本身是金矿:它标记了知识库的缺口,把缺口补回去,系统才会越用越强。

## 方案

### 1. 零成本置信度闸(`app/core/confidence.py`)

四个信号**全部来自检索/精排结果,零额外模型调用**:

| 信号 | 含义 | 权重 |
| - | - | - |
| top1_score | 精排 Top1 的 rerank_score | 0.5 |
| valid_count | score ≥ 0.3 的条数,3 条封顶归一 | 0.2 |
| margin | Top1-Top2 分差 | 0.2 |
| key_clause_hit | Top3 命中关键条款词表(与入库同款启发式) | 0.1 |

分数 < 阈值 → `evidence_strong=False` → 条件边 `confidence_gate` 路由到兜底话术 + 转人工(`app/graph/routing.py:25-27`)。**分数过线后还有第二道语义闸**:`selfcheck` 让 LLM 判证据是否够答(`nodes.py:200-206`)。两道闸都在「检索后、进 Agent 前」。

### 2. 落池(`app/graph/nodes.py:128-148`)

兜底回复的同时写 `low_confidence_questions` 行:用户原话、失败来源三枚举(分数闸/语义闸/用户反馈)、完整信号 JSON、Top3 召回快照。快照三态语义:**列表**=走了检索有召回;**[]**=走了检索零命中(「真缺知识」强信号);**NULL**=没走检索。

### 3. 批处理飞轮(`app/core/flywheel.py`)

用户拍板走**定时批处理**而非近实时。一次 LLM 调用输出三件套 `{标准化问题, 命中候选id, 建议答案}`:
- 命中候选 id → 只 `increment_occurrence`(原子 UPDATE,**驳回即终审,不复活**);
- id 不在候选列表 → 幻觉,跳过、游标留在原地下轮重试;
- 没命中 → 新建 `review_queue` 行。

串行 + 游标回写:天然幂等可重跑;同批同义问题第二条能命中第一条刚建的行。

### 4. 人工审核闭环(`app/api/review.py`)

队列按 `occurrence_count` 降序——「一个缺口被越多用户反复问到,越该优先补」。**通过** = 建 Chunk(「飞轮沉淀」)→ 写 MySQL → 向量化 **同步完成**才置「通过」,保证「点了通过,下一问就能检索命中」;写回失败 → 回滚、返回 502、保持待审可重试。驳回/通过都是终态,仅「待审」可流转。

### 5. 趋势守护(`scripts/eval_flywheel.py`)

定期(建议每天 6:00)把 Recall@5/MRR/Faithfulness/拒答率落 `eval_runs` 表连趋势,任一指标下滑 >0.005 标 ⚠——验证「飞轮写回没把质量拉下来」。权威源是表,页面直接读表,不读文本报告。

## 关键参数与实测

- 权重固定为模块常量**不进 settings**:校准的是阈值不是权重——YAGNI,别造两层可调(`confidence.py:10-11`)。
- 阈值 **0.26 是校准产物非拍脑袋**:在 ch04 评估集上扫阈值取 Youden J 最大点(`scripts/calibrate_confidence.py`)。校准数据:可答桶 p50=0.715,应拒桶 p50=0.105/max=0.251;t=0.26 时可答通过率 85%、应拒放行率 0%、YoudenJ=0.850。
- 最新趋势轮:Recall@5=0.986、MRR=0.897、Faithfulness=1.000、拒答率=0.983。

## 设计取舍与坑

- **selfcheck 失败按 fail-closed(证据不足)处理**:判不足最多让用户看到兜底话术,放行可能编出一段假政策——代价小的一侧优先。
- **驳回即终审**:查重命中任何状态的候选都只累加 occurrence_count,不复活已驳回的条目。
- **`JSON(none_as_null=True)` 不能省**:默认会把 None 写成 JSON 'null',`IS NOT NULL` 判真、快照三态语义全乱,实测踩坑(`app/db/models.py:131-132`)。
- 落池 reason 里塞完整信号 JSON,审核人能看出闸为什么拦;「证据其实够、却记着 self_check 兜底」的条目正是这道闸出过故障的线索。
